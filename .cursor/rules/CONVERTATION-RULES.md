# Правила конвертации для аудио текстов

В этом документе описаны правила конвертации исходного JSON-файла с разметкой текста песни из Suno в формат, подходящий для караоке-приложения.

## Типы данных итогового JSON

```typescript
export interface WhisperResponse {
	text: string;
	segments: Segment[];
	language: string;
}

export interface Segment {
	id: number;
	seek: number;
	start: number;
	end: number;
	text: string;
	tokens: number[];
	temperature: number;
	avg_logprob: number;
	compression_ratio: number;
	no_speech_prob: number;
	words: Word[];
}

export interface Word {
	word: string;
	start: number;
	end: number;
	probability: number;
}
```

## Основные правила конвертации

### 1. Общие принципы

- Исходный файл (`{название_песни}.json`) содержит массив `alignment` с информацией о каждом слове/фрагменте текста
- Итоговый файл (`{название_песни}-converted.json`) должен содержать полный текст песни в поле `text` и массив `segments`, где каждый сегмент соответствует абзацу текста

### 2. Формирование сегментов

- **Создание сегментов из абзацев**: Каждый сегмент должен соответствовать одному абзацу из файла `{название_песни}.txt`
- **Идентификация абзацев**: Абзацы определяются по двойным переносам строки `\n\n` в исходном тексте
- **Идентификаторы**: Каждому сегменту присваивается уникальный числовой идентификатор `id`, начиная с 0
- **Обработка повторяющихся абзацев**: Повторяющиеся абзацы (припевы) должны обрабатываться как отдельные сегменты с уникальными временными метками

### 3. Временные метки

- **Start и End**: Для каждого сегмента устанавливаются временные метки `start` и `end`, соответствующие первому и последнему слову в абзаце
- **Формат времени**: Все временные метки должны быть представлены в секундах с плавающей точкой
- **Уникальность временных меток**: Сегменты с идентичными временными метками должны быть объединены или отфильтрованы

### 4. Обработка слов

- **Сохранение исходных данных**: Каждое слово в сегменте должно сохранять свои исходные временные метки
- **Сохранение пробелов**: Поле `word` может и должно содержать пробелы для правильного форматирования текста
- **Обработка разделенных кавычек**: Система должна корректно обрабатывать случаи, когда кавычки или апострофы разделены между словами

### 5. Особенности обработки текста

- **Метаданные и теги**: Удалить метаданные типа `[Verse]`, `[Chorus]`, `[Bridge]` из конечного текста
- **Разделённые слова**: Не объединять разделённые слова (например, "sme lls" должны остаться в таком же виде)
- **Формат текста**: Текст сегмента должен сохранять все пробелы между словами и переносы строк внутри абзаца из исходного файла
- **Повторяющиеся переносы строк**: Множественные последовательные переносы строк (`\n\n\n`) должны быть заменены одним переносом (`\n`)

### 6. Игнорируемые поля

- Поля `tokens`, `temperature`, `avg_logprob`, `compression_ratio`, `no_speech_prob`, `seek`, `probability` могут отсутствовать в итоговом JSON

### 7. Обработка специальных случаев

- **Служебные метки**: Если в исходном тексте присутствуют метки типа `[Verse]`, `[Chorus]`, они не должны создавать отдельные сегменты
- **Пустые строки**: Пустые абзацы в `{название_песни}.txt` должны быть пропущены
- **Кавычки и апострофы**: Сохранять кавычки и апострофы в исходном виде, независимо от их позиции
- **Сортировка сегментов**: Сегменты должны быть отсортированы по времени начала для корректного последовательного воспроизведения

## Пример конвертации

### Исходные данные (home-office.json):
```json
{
  "alignment": [
    {
      "word": "[Verse]\nMy",
      "success": true,
      "start_s": 17.79255319148936,
      "end_s": 18.03191489361702,
      "p_align": 1
    },
    ...
  ]
}
```

### Итоговые данные (home-office-converted.json):
```json
{
  "text": "My T-shirt smells like office chair\nThere's coffee spilled all over it...",
  "segments": [
    {
      "id": 0,
      "seek": 0,
      "start": 17.79255319148936,
      "end": 32.79255319148936,
      "text": "My T-shirt smells like office chair\nThere's coffee spilled all over it\nYou text me \"let's meet over there\"\nBut I can't go\nI won't go",
      "words": [...]
    },
    ...
  ],
  "language": "en"
}
```

## Алгоритм конвертации

1. Прочитать исходный файл JSON (`{название_песни}.json`)
2. Прочитать файл с текстом песни (`{название_песни}.txt`)
3. Удалить метаданные и служебные метки из текста
4. Предварительно обработать слова для исправления проблем с кавычками и знаками препинания
5. Разделить текст на абзацы
6. Для каждого абзаца найти все его вхождения в полном тексте
7. Для каждого вхождения абзаца определить соответствующие временные метки
8. Исключить дублирующиеся сегменты с одинаковыми временными метками
9. Сортировать сегменты по времени начала
10. Сформировать итоговый JSON-объект
11. Записать результат в файл (`{название_песни}-converted.json`)
